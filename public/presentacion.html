Notify

Un asistente de IA que vive adentro de tus Pull Requests: detecta cuándo la documentación quedó atrás, la redacta, y solo la publica si vos decís que sí.

El problema

El código avanza. Los docs, no.

Se agrega un endpoint, se cambia un comportamiento, se refactoriza un módulo entero — y nadie actualiza la documentación. No hay ningún proceso que lo obligue.

Con el tiempo, el equipo deja de confiar en los docs y empieza a leer directamente el código fuente para saber qué hace algo.

app/api/notifications/route.ts
+ export async function POST(request: Request) {
+ const { email, message } = Notification...
docs/api.md
(sin cambios — nadie lo tocó)

La solución

Un asistente que vive adentro del flujo de PRs

No es un chatbot aparte. Se integra al proceso que el equipo ya usa.

01 · Analiza

Cada Pull Request

Impacto, si requiere doc, si ya la actualizó, y qué archivos afecta — automático en cada push.

02 · Genera

Lo que nunca se escribió

Detecta módulos sin documentación y redacta un primer borrador, sin mandar el repo entero.

03 · Controlás vos

Nada se publica solo

Cada borrador se acepta, edita o rechaza a mano antes de convertirse en un PR real.

Demo B

Automático en cada push

Un webhook escucha cada apertura, commit y merge. El sistema comenta directo en el PR — y si vuelven a pushear, edita ese mismo comentario en vez de duplicarlo.

Colaboración

Cada persona publica a su nombre

Login con GitHub vía OAuth: los PRs que se crean quedan atribuidos al colaborador que los generó, no a una cuenta compartida.

Si alguien nuevo entra sin acceso, un botón abre un Issue asignado al dueño del repo — GitHub avisa por email. Vos aprobás manualmente, nada queda automático.
